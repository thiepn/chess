## Directly demonstrated defects and source repairs
1. P113 `MasterGameLibrary` uses `confirmLeavingVariation` when scrubbing move history, selecting a different decision and restarting a legal alternative, but the visible **Reset to historical position** button discarded an unsaved SAN variation without consent. P125 brings it under the same original cancelable confirmation before any state changes.
2. The top-level **Complete games** and **Compare strategic decisions** tabs bypassed the same confirm guard and could discard an ongoing unscored eight-ply variation. These mode switches now respect the existing cancel outcome.
3. P114 `CrossGameTransferLab.choose(id)` ran its clearing logic even when clicking the already selected pair. This instantly erased a learner's prepared/pasted, not-yet-copied portable note without the existing change-pair warning. Clicking the active case now leaves it intact. Switching to another pair still uses the existing explicit confirmation.
4. P115/P121 `CounterfactualLab` retained its previously qualified source `challenges` and `guidance` during a retry or source change, potentially showing stale source claims until validation completed. Source state is now cleared when refetch begins; canonical hydration must complete before displaying the original witness text.
5. Review's `ReviewView` returns one `GameStoryView` component for every saved game route without an identity key. Its `selectedPly`, `preview`, `lineStep` and original board position use state initializers and could carry across routes to a different game. P125 keys the subview to the existing immutable game ID, not the current FEN, so route transitions reset per-game controls without re-mounting on every ply.
6. Two focused browser tests authored: a P114 active case with generated portable note retains its exact contents, and the P124 original review board DOM is stable during same-game notation navigation. Tests are **NOT_RUN**; no broad test suite or CI triggered.
